## 二、"用什么解决什么问题"——含金量在这（面试谈资）

| 遇到的问题 | 用什么机制解决 |
|------------|----------------|
| 模型**嘴上说做了、实际没调工具**（幻觉式完成） | 意图识别 + 完成声明模式匹配的 `check_claim` 校验，检测到"口头完成"强制重调 |
| 对话变长 **token 超限**，又不能直接丢历史 | 两级摘要压缩（粗/细）+ 早期消息归档入库，用 BM25+向量混合检索按需召回 |
| embedding 对短文本**区分度不足**，纯相似度判记忆冲突误判 | 双阈值：相似度只做召回，中段结果交 LLM 做语义判定（阈值管召回、LLM 管判定） |
| 多会话/多用户**数据串号** | 隔离条件焊死在 SQL（session_id/user_id），不依赖调用方自觉 |
| 复杂任务模型**走一步看一步、失败就卡死** | 显式 PlanState 状态机：规划→执行→自评→失败决策（中止/跳过/改计划） |
| 目标**跨对话无法接续** | goals 表 + next_step 状态机，agent 读"留给未来自己的下一步"继续推进 |
| 只会被动应答 | daemon 调度线程定时唤醒，防空转/防伪造输入/防日期幻觉 |
| MCP SDK 是 async，Agent 工具是同步 | 后台守护 event loop + `run_coroutine_threadsafe` 桥接，长连接钉死在固定 loop |
| 外部 CLI（飞书）不是 MCP server | 薄包装层 subprocess 桥接，把命令行能力标准化成 MCP 工具 |
| 外部服务挂了拖垮主流程 | 进程级单例 + 全失败降级纯本地 + `DISABLE_MCP` 开关 |

## 四、一定要提前准备的面试追问（否则会露怯）

简历这么写，面试官大概率追问这几个，你要能用大白话讲清：

1. **"check_claim 怎么判定口头完成？误报怎么办？"** → 答：宁可漏检不可误报，意图词+严格动作短语双重过滤，回顾性措辞走黑名单豁免。
2. **"为什么冲突判定要加 LLM，不直接用向量阈值？"** → 答：embedding 对短文本不敏感，阈值当高召回过滤器，语义裁决交给 LLM。
3. **"MCP 后台为什么要单独一个线程跑 loop？"** → 答：ClientSession 绑定创建它的 event loop，不能每次调用临时 asyncio.run，否则连接失效。
4. **"自驱和定时脚本有什么区别？怎么防它瞎转？"** → 答：触发源不同执行路径相同；靠 next_step 约束、实质进展才记日志、日期锚点防幻觉。
5. **"这是你一个人做的吗？数据量/QPS？"** → 诚实说是个人学习项目，重点在机制完整性而非规模——**别编流量数字，一问就穿。**
